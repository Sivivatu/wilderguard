# Error reporting implementation plan

Scope: automatic unhandled JavaScript errors/rejections and Android JVM/NDK crashes using official Sentry Capacitor 4.5.0. No gameplay analytics, replay, logs, sessions, tracing, profiling or release publication. Worktree starts at 3983d21. The initial implementation excluded commits and source uploads; the owner subsequently requested a commit and push for review. Source stays private, and a private review remote must be identified before pushing.

Architecture: isolate lazy SDK startup from gameplay; require valid Cloud DSN, explicit beta/public environment, release/build and the owner-selected automatic policy. The owner selected automatic reporting, a first-run privacy notice and an off switch, using Sentry Cloud EU. Missing project configuration keeps reporting disabled. Keep reporting preference separate from campaign saves. Apply an event allowlist in JavaScript and Android. Override the official native plugin's initialization to enforce native settings, with an event-only transport to cover cached envelopes that bypass beforeSend. Keep error messages redacted; retain exception types and bounded stack locations. Native crash files can contain unsanitized local diagnostics until Android processes them; never send attachments.

Validation sequence: tests for gating, sanitization, failure isolation and queue bounds before implementation; full unit/coverage and browser/offline regression checks; native sanitizer/transport unit tests and Android beta build. Separately prove Cloud ingestion, readable stacks and physical-device overhead/crash delivery only after project access is available. No permanent crash trigger in gameplay.

Sources checked 6 November 2026: official Capacitor quickstart, getsentry/sentry-capacitor v4.5.0 source and npm registry, Sentry Java 8.61.0 options/OutboxSender/transport source. The SDK supports Capacitor 6/API 22/Java 17. Its JS options do not forward native privacy/cache controls, requiring a small native adapter. User/project supporting common rules were unavailable; supplied AGENTS.md policy applies.
